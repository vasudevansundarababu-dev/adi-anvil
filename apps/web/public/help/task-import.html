Anvil task import — foundation v1

Approved Objective → Import tasks → upload CSV/JSONL → map → validate → publish → attach to suite → Configure run.

Required fields

TaskSpec 1.0 requires schema_version, external_id, instruction and input. Input is a JSON object. Title, reference and metadata are optional. CSV requires explicit external_id, instruction and input mappings; schema_version defaults to 1.0. Reference answers are excluded from actor previews.

Errors

  • REQUIRED: supply the named field or mapping.
  • INVALID_TYPE: correct the JSON type.
  • INVALID_JSON: correct the JSON line or nested cell.
  • DUPLICATE_EXTERNAL_ID: give both reported rows distinct IDs.
  • UNSUPPORTED_SCHEMA_VERSION: use 1.0.

Jobs

UTF-8 CSV/JSONL only, 25 MiB, 10,000 tasks, 128 KiB CSV cells and JSON depth 32. The worker commits 200-record logical chunks. Cancel stops further chunks; retry retains committed progress, with three explicit retries and ten unfinished jobs per project. Raw files remain quarantined; parsing does not certify malware safety.

Versions and execution

Publication requires completed validation and the same approved objective revision. Corrected files create new versions. Runs bind exact version IDs, never latest. Arbitrary imported tasks need qualification and a supported adapter before execution; fixture answers cannot evaluate them.

Privacy and help

No automated PII detection or redaction exists in this increment. Use authorized non-sensitive sources only. Help is static and read-only, with no server/model receiving questions or data. Reset clears its in-memory conversation. It cannot publish, approve or start runs. PDF, Parquet, remote connectors, generation and privacy processing are later increments. Synthetic examples are not Bodhium cases or model-performance evidence.
