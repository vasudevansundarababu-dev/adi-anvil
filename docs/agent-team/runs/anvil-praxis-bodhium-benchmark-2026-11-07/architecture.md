## 3. Components and trust boundaries

```text
Praxis offline export (untrusted archive; no live Praxis dependency)
  -> bounded intake/quarantine -> immutable bundle receipt + restricted original bytes
  -> validated manifest and separate actor / evaluator projections
  -> deterministic SME compiler -> actor-only Harbor packages
                               -> digest-bound reviewed evaluator registry
  -> G1..G5 and native qualification records
  -> benchmark/suite revision -> frozen three-model protocol
  -> server readiness + exact Admin admission + candidate/judge reservations
  -> PostgreSQL jobs/leases + LangGraph orchestration checkpoints
  -> dedicated Harbor worker -> no-egress candidate tools / host inference broker
  -> sealed outputs -> separate evaluator worker/container -> judge broker if authorized
  -> immutable criterion/score revisions -> redacted scorecard/export -> human publication
```

Keep Next.js/React/TypeScript styling and existing modern navigation, FastAPI, PostgreSQL canonical records, LangGraph orchestration, Neo4j rebuildable evidence projections, and existing Keycloak OIDC. No new queue product or parallel identity store. LangGraph/checkpoints describe progress; unique database rows/leases/dispatch intents enforce financial and execution correctness. Neo4j never decides authority or computes the official score.

Proposed focused modules (not created): `benchmark_bundle.py` (strict contract/intake), `benchmark_compiler.py`, `benchmark_qualification.py`, `benchmark_protocol.py`, `benchmark_execution.py`, `benchmark_evaluation.py`, `benchmark_scores.py`, `benchmark_api.py`. Extract shared admission/broker/collection helpers only where needed; keep old adapter entry points and compatibility behavior intact. Avoid a second general-purpose execution engine.

## 4. Versioned source, contract and compilation

New discriminator: `praxis.anvil.benchmark_bundle.v1`, adapter `sme-artifact-v1`. Use the manifest's version, not filename guessing. Legacy `task.v1/v2/v3` and `export.v1` validators and labels are unchanged. `contract-design.md` defines request/response shapes and illustrative non-proprietary contract sketches; no schema/code file is implemented in this stage.

### Intake and authenticity

- Initial pilot limits: 100 MiB compressed, 500 MiB expanded, 5,000 regular files, 50 MiB/file; bounded depth/path/header metadata and per-project upload quotas. Enforce both compressed and expanded streams, including chunked requests and aborts, before durable acceptance. Exclude special/link types, absolute/parent/drive/backslash paths, controls, alias/case/Unicode collisions, duplicates and auto-run hooks. No imported code runs at import/build/preview.
- New dedicated streaming upload route must bypass **only** the body buffering path for this bounded route. Existing `RequestLimits` buffers whole bodies (1/3/26 MiB route limits), so merely raising `/artifacts` limits is not a safe implementation. Spool with byte counting into a private staging directory; validate; atomically record content-addressed references. Retain rejected/quarantined originals per policy; clean only owned incomplete staging files. Disconnects cannot create an accepted receipt.
- Manifest lists every payload path/hash/size/visibility, exporter identity and immutable bank/task versions, source owner/classification/rights references, environment OCI digest, allowed tools, outputs, criterion identities/maxima, scoring and compiler/evaluator requirements. Reject undeclared files, duplicate JSON keys, nonfinite numbers, incompatible semantics and conflicting versions.
- Proposed signature profile: detached Ed25519 over RFC8785 canonical UTF-8 `manifest.json` bytes, with explicit profile ID. Manifest excludes itself and detached signature from its payload hash list; every other payload is hashed. Preserve original manifest/archive bytes and canonical signed bytes separately. Trust roots/key validity/revocation policy are Admin-configured outside the bundle; an included public key is not trusted. Unknown/unsigned signer => quarantine, never Verified. A separately audited unverified-source exception, if the Product Owner later permits one, does not waive rights/completeness/qualification. No exception is selected now.
- Same project + exporter identity + bank ID + bank version + exact archive bytes => same receipt. Same immutable source/version with changed bytes => 409, including a repackaged archive; successor version required. Record both archive and canonical manifest hashes. Source project/reviewer IDs are lineage only, never destination selection or Anvil permissions.

### Private separation

Original archives contain BOTH actor and private data, so they are private evaluator-source material, not an ordinary `internal` or `actor` download. New raw/evaluator artifact classes use separate storage namespace/mount and explicit assigned-reviewer policy. The candidate package contains only selected task actor assets, output contracts and tool declarations. It contains no eval pack, fixtures, rubric implementation, private judge template, signature secret or another task's files. Public criterion summaries may be projected only if their disclosure is authorized; private numeric tolerances/oracles never are.

`artifacts.py` currently stores UUID object keys and verifies SHA-256; it is not a content-addressed vault or an evaluator isolation service. Extend metadata/access handling and use a project/access-class/SHA-256 namespace for new benchmark objects. No cross-project dedup information leakage. Existing object paths stay valid. Candidate worker and candidate mount configuration must not gain evaluator-vault access, including indirectly through generic routes, package manifests, notebooks, error bodies or traces. `api.artifact_content` currently special-cases `hidden_reference` only; adding an enum alone is insufficient. New private classes must be denied by the generic endpoint, and gated in `artifacts.read`, worker database grants/RLS, run evidence, export and package routes. A trusted evaluator service receives an individually authorized job input projection, not arbitrary artifact-ID access.

### Deterministic compiler and qualification

Compiler binding includes source hashes, compiler version, Harbor 0.25.0, actor projection digest, tool-server versions, environment OCI digest/kind, output contract and reviewed evaluator implementation/image digest. Reproducible packages use ordered entries, fixed archive metadata and hashed generated files. An imported `run_judge.py` is inert quarantine content; only an installation-reviewed registry implementation can become an evaluator binding. No image auto-build/pull, dependency install or SDK inference at import. Images must be authorized and qualified separately.

A new SME package retains Markdown deliverables plus explicitly declared sidecars. BL-001 `valuation_report.md` (900s), BL-002 `pr_strategy_memo.md` (600s), BL-003 `financial_matching_analysis.md` and SME-approved assignment/checkpoint sidecar (1200s). Do not derive the absent sidecar's fields/oracle or 81 criteria from the PDF. Generic adapter ceilings must permit this profile (proposed ≤1800s per task, with 1200s gateway/client timeout compatibility verified); old preparation ≤600s remains unchanged. Candidate 2 GiB/1 CPU/64 processes, tool timeout ≤60s and remaining task time, isolated tmp/home/output with total output quota are proposed pilot settings; resource/tool/output quotas freeze with the protocol and are installation-capped. Preserve max 15 inference turns; cap tool calls/bytes per turn explicitly (proposal: 8 calls, 64 KiB arguments/result each, 16 MiB total collected outputs), subject to actual exhibit review. No current 32 KiB prompt/2048 token legacy cap is silently widened; new provider context/output bounds must be selected and cost-qualified for the SME profile.

G1 integrity/completeness (signature, files, all criterion maxima); G2 actual actor/evaluator isolation with private canaries and access attempts; G3 effective non-root/no-egress/no sockets/metadata; G4 supplied-image stdio tool schemas, real calculation, timeout/memory/owned-process-tree limits; G5 fresh read-only inputs/scratch/home and sealed regular-file outputs. Shared actor/evaluator numbers require provenance/disposition rather than naive string-equality rejection. G1..G5 and native trial receipts bind every digest; changed evaluator/image/tools/compiler marks qualification stale. Native Harbor positive/empty/guardrail trials for every complete case and separate good/bad/boundary/injection SME calibration are mandatory. Fixture machinery results are not candidate performance. Missing real Bodhium material => Awaiting source/Blocked, not Ready.

## 6. Frozen protocol, broker and durable execution

Freeze exactly three slots (proposed provider families OpenAI, Anthropic, Gemini; exact model IDs are unfilled), selected current model/config/key versions and destinations, supported controls/unsupported control declarations, adapter versions, actor inputs/tools/image/evaluator/rubric hashes, repetitions=2, ordering/seeds, deadlines, 15-turn limit, all output/resource limits, valid-trial/retry/cancel rules and distinct candidate/judge cap/expiry/pricing/rights. New sampling/settings or repetitions => new protocol and approval; provider-returned model mismatch => typed unresolved outcome, never silent substitution.

A turn is one candidate inference response, including all requested tool calls. Introduce a normalized host conversation envelope with response ID, provider-returned model ID, ordered content/tool calls `(id,name,arguments)` and observations linked by call ID, finish reason and normalized usage. Qualify each provider's actual SDK wire contract, multi-call handling, error observations and final text separately. Native tool calling is a new adapter profile; the current single-JSON-action path stays versioned/unchanged. No candidate-side SDK/network/key, legacy OpenAI-global-key fallback, redirect, environment proxy override or automatic retry. Host stdio bridge admits only frozen schemas and canonical workspace paths; parallel requested tool actions execute in deterministic declared order unless independence was explicitly frozen. Refusal/limit evidence is retained, not rewritten as success. Actual model/task smoke for each selected provider is a later separately paid gate, not satisfied by native scripted actors or mocked wire responses.

### Scheduling and money sequence

1. Draft/freeze creates immutable records only. Readiness GET/estimate is side-effect-free for product admission: no provider call, job, reservation, signing-key trust change or approval. Existing session bookkeeping is not financial admission.
2. On launch, validate CSRF/session/role, exact current subject/hash and rights destinations/expiry, runtime activation, all package/adapter gates, reviewed candidate/judge settings, capacity and known conservative pricing bounds. Current Admin Run controls apply; snapshot all child subjects and both purposes. Create exclusive candidate/judge spend windows and idempotent reservation rows atomically with launch/jobs. Do not dispatch in an API transaction.
3. Candidate attempt reservations cover worst-case 15-turn usage under that protocol; judge reservations cover configured grading plus authorized second-review policy. Use `budget_reservations` with unique purpose-bound operation keys. The new benchmark reserve service uses window counters and frozen benchmark spend bindings; do not call legacy `budget.reserve` (which requires the single-window `run_budgets` row) and do not double-reserve group caps. Candidate per-turn `harbor_agent_calls` account within the attempt envelope, not as a second debit. Judge calls use their own equivalent call table. Existing standalone workspace group reserve/reconcile paths remain unchanged. Benchmark-owned group endpoints must reject bypass launch/reservation.
4. Claim at most three active candidate attempts per comparison, with lower provider-specific concurrency/rate quotas. Acquire capacity and job lease atomically with a fenced attempt; use deterministic reproducible interleaving over tasks/slots/repetitions. Benchmark-owned children use independent eligibility, not legacy predecessor-success checks. Legacy groups preserve current sequential behavior. Valid model failure does not suppress other benchmark cells; admission-wide revocation stops future dispatch.
5. Commit durable dispatch intent, request/input hashes, turn index and financial reservation **before** network call. Release DB locks/transactions. Broker sends once. Tool work and artifact reads/writes also run outside locked transactions; seal/hashes are prepared before attaching refs. Re-enter a short fenced transaction to capture outcome/usage/output-seal/event exactly once. External execution cannot be made exactly-once by PostgreSQL: crash after intent/before or during send => `dispatch_unknown`, reservation/capacity conservatively retained, no redispatch. Only proven pre-dispatch failure can retry under frozen policy.
6. A trusted broker call failure with unknown billing/model usage remains Unknown even if a human-facing error is recognizable. Reconciliation is an audited append-only evidence decision with provider receipt/request ID and actual charges or proof of no dispatch. If charge exceeds conservative bound, stop affected purpose/raise a financial incident; never clamp charges or release unknown money. Signed operator reconciliation does not manufacture a missing model answer or a scored cell.
7. Candidate ends, owned tools/process tree stops, outputs are validated as regular bounded files, made immutable and hash-sealed. Queue evaluation immediately for that task/attempt; never wait for other tasks. The evaluator receives only sealed outputs plus approved private inputs. Judge network goes solely through a distinct authorized host broker, not arbitrary evaluator-container egress. Job/score/counter/audit finalization is transition-once with unique effects.

### Locks, cancellation and resume

Preserve recovered `worker.lock_run`: project fence → run → job/episode. API idempotency already locks the project FOR UPDATE; worker project_fence uses KEY SHARE, not an unsafe shared-to-exclusive upgrade. New benchmark paths use project fence → comparison run → ordered group/plan/check/cell/job rows. Any combined finance update uses **window → owning run/binding → reservation** (the existing ledger discipline); never call a window-locking budget helper after taking run/cell locks. Split financial capture and execution finalization into idempotent transactions/events if necessary rather than reversing the lock order. Admission takes project serialization then windows then run/children. Shared helpers must document this global partial order, including deterministic ordering for multiple windows/children. No network or artifact I/O while locks held. Recovery of omitted r6 concurrent finalization/deadlock tests is required before implementing these extensions.

Cancellation writes a durable cutoff/fence under the run lock. New dispatch intents after cutoff are denied. Queued attempts become cancelled with proven unused reservations released; running attempts stop only owned sandbox/process identities, seal available evidence and reconcile incurred/unknown charges. If completion was committed before cutoff it remains completed; if cutoff wins, late capture is retained as evidence/usage but cannot advance to an official passing result. Evaluation committed before cutoff remains historical evidence; pending evaluator work follows the frozen cancel policy and no new judge dispatch occurs. Do not delete sealed results, kill unrelated PIDs or delete volumes. A stale lease/result cannot change a newer terminal state or counters. Unknown active processes retain their capacity quarantine until reconciled, preventing oversubscription on restart.

Resume only a proven safe pre-dispatch checkpoint or sealed-output evaluation checkpoint with fresh rights/admission and no ambiguous call. An unknown candidate/judge dispatch blocks automatic resume. Rerun uses an explicitly authorized linked new attempt and additional allocation; the initial 18-cell plan and original results remain intact. Results show attempt history; a replacement's inclusion requires an explicit successor comparison/policy binding, never best-attempt selection.

Separate source (received/validating/quarantined/accepted/superseded), package (draft/building/qualified/failed/stale), protocol (draft/frozen/blocked/admitted/revoked), execution (queued/running/collecting/completed/model_failed/operational_failed/dispatch_unknown/cancelled), evaluation (pending/running/scored/review_required/failed/adjudicated) and publication (private_draft/reviewed/published/withdrawn) dimensions. These are typed projections/events, not one Ready flag. Resolved terminal operational failure can end scheduling while leaving the comparison incomplete/unrankable.

## 7. Scoring, review and comparison policy

The generic profile supports SME-declared point maxima and criterion counts; the Bodhium acceptance profile requires exactly 81 explicitly supplied criterion records with task maxima 24/6/51 (BL-003: 10 assignments + 41 justification checkpoints). No absent criterion, oracle, WACC, company match, certification or tolerance is invented. Task/source completeness is a gate, not a prompt-engineering exercise. SME must decide semantic equivalence, PR instruments/certification necessity, units, rounding, relative/absolute tolerance composition and required sidecar extraction.

Use exact Decimal/rational arithmetic with a declared scale for any fractional credit. Sum raw points first, divide by 81, then round only displayed percentages to two decimals with a frozen display rule (proposed half-up). Store raw earned/max points and score-policy version, never sum rounded task percentages. Complete repetition score = `100 * (BL001 + BL002 + BL003) / 81`. Mean only complete required suite repetitions, with per-repetition totals and observed range. An equal-task macro average is a separately labeled secondary metric, never the primary denominator. Two repetitions describe this pilot, not statistical significance or broad model superiority.

If any required model/task/repetition is missing, operationally invalid, ambiguous, unscored or awaiting mandatory review, the model is **Incomplete / primary comparable score=null**, even if another repetition is complete. Complete-repetition diagnostic means may be shown with exact included/excluded counts but not ranked. All tasks are independently evaluated when sealed; suite completion requires all required cells resolved. A model-caused deadline/turn limit/missing deliverable gives zero only for affected required-output criteria under the frozen valid-trial policy and retains its reason. Operational outage, evaluator failure, rights loss, infrastructure timeout or ambiguous dispatch is not a model-quality zero. Attributed model vs infrastructure failure must have evidence; uncertain attribution => unresolved. A declared hard safety constraint may zero official task reward while retaining raw diagnostic criterion points and violation evidence. This distinction is frozen before runs.

Judge output must cover every expected criterion exactly once; no extras, duplicates, out-of-bounds or NaN credit, unbound task/output versions or invented citations. Evidence is exact byte/span offsets into hash-sealed deliverables (with declared UTF-8 decoding), verified server-side. Totals are recomputed, not trusted from judge JSON. For an absent-output deterministic zero, use a typed absence event rather than a fabricated output citation. Contradictory/malformed judge data => failed evaluation/review_required, never zero or automatic repeated paid judging. The judge sees only necessary blinded task/rubric/output content and no candidate identity/cost/rank, cannot execute candidate text or browse external references, and requires explicit destination rights. Private judge prompts/oracles/traces remain evaluator-only; viewer criterion drilldown shows authorized ID/points and output evidence, not private reasoning/reference text. Do not request hidden provider chain-of-thought.

Calibration requires SME-owned positive/negative/borderline/paraphrase/keyword-deception/injection cases and numeric tolerance boundaries; freeze evaluator/judge/config/calibration approval. Candidate and judge roles/keys/budgets/traces are distinct. Deterministic evaluator checks are deterministic; model judging is not, even at low temperature. No approved judge means semantic scoring is blocked, not replaced by an invented judge. Local deterministic conformance can be planned separately.

Reuse the intent of `evaluation.needs_second`, `sampled`, `grading_position` and `domain` assignment/independence checks: critical/disputed, within five percentage points of a declared task pass threshold, and reproducible frozen 10% sample get second review. If thresholds/calibration policy are absent, freeze is blocked rather than assuming them. Use task point percent, not the legacy assessment scale. Sampling binds protocol + stable cell ID (not a rerun's success). Distinct assigned adjudicator cannot be the first grader; all corrections create immutable successor score revisions with evidence/rationale. Reviewer assignment alone does not grant judge-provider spend.

Unknown usage/cost is null with `cost_status=unknown`; known subtotal and estimate are separate fields, never `$0` for missing data. Historical published references require citation, date and explicit task/tool/protocol/judge comparability/rights. Illustrative 64/81 or 50.62% figures never populate measured results. ## 9. Alternatives, migration, compatibility and rollback

Rejected: raising v3's rubric cap and relabeling real data synthetic (breaks provenance); placing private eval under mode0700 inside candidate container (mount is still exposed); running imported judges or candidate-side SDKs (credential/network breach); reuse of legacy ≤2-candidate protocol as-is (not supported); parallel new app/catalog/queue (duplicate ownership); whole-archive memory buffering; launching three unrelated groups with independent approval/reservation (no atomic frozen comparison); in-memory concurrency; claiming exactly-once vendor billing; best-attempt scores; image extraction as complete Git recovery.

Chosen tradeoff: three per-package groups under a new canonical run/protocol parent requires scoped admission/claim extensions, but preserves existing preparation FK and models/runs tooling. A full generalized multi-package group redesign is larger and not required. Separate evaluator identity/vault is operational work, not merely Python filtering; its local Compose/service isolation must be verified before release. Native provider tool loops cost more qualification effort than JSON action prompting; keep both versioned and block unsupported selected profiles.

Migrations are additive and feature-gated, with fresh and upgrade checks against recovered complete source before any rollout. Preserve existing source/user changes, credentials and persistent records. No automatic migration/deploy or global dependency installation here. Locks are independently updated only when implementation later requires an actual reviewed dependency. Do not upgrade Harbor to follow upstream docs. No real Bodhium data in source control without separate express rights.

Rollback plan (not execution authority): revoke new dispatch admission, stop/drain only benchmark-owned queues/processes while preserving unknown reservations/evidence, disable benchmark UI/API activation, and restore previous application image/config through a separately approved exact-target procedure. Retain additive schema/tables/RLS so prior versions continue to function; do not drop tables/private objects or replay unknown calls. Verify old images safely ignore new rows/modes before claiming rollback supported; ordinary worker job ownership must remain restricted in both forward and rollback builds. A prior image whose claim function can seize new jobs is not a safe rollback until jobs are drained/ownership fenced. Any backup/snapshot/restore/cloud action needs new authorization; none is performed by this design.
