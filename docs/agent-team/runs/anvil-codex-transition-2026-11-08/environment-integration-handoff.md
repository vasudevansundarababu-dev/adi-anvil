# Six-environment local integration delivery

This implements the authorized local integration work after `05ebf16`. It does not certify the complete cloud/authentic-model acceptance of specification 2.0. Praxis and the original checkout are untouched. Paid calls, cloud provisioning, publication and deployment remain off.

## Implemented behavior

- The six reference templates retain thirty materialized synthetic scenarios with real PostgreSQL records, generated files, typed tools, immutable evidence and reset. Local Build is a durable four-phase job with resume/cancellation and exact profile/manifest receipts.
- Registered environments can be selected in reusable Execution Groups. Runs freeze the source Project/Task, environment/pack, condition, harness, evaluator configuration and repetition. Existing benchmark tables, seven views and score formulas remain in use.
- Every attempt gets a fresh instance. Dispatch intent commits before external execution. Lost/uncertain attempts retain available evidence and cannot be silently replayed. Retry creates a linked new Run and new instances; original attempts and report decisions remain unchanged.
- The local component harness, local episode protocol, installed OpenEnv 0.12.0 interpreter and installed Harbor 0.25.0 harness connect actual captures to assessments and exports. OpenEnv diagnostic reward never replaces Task grading.
- Harbor uses an exact cached image, a nonroot/read-only/no-network actor, bounded resources, explicit output collection and a separate verifier consuming sealed trusted evidence. Actual actor probes cover private-file denial, egress denial, read-only inputs and resource limits. Business component state is host-mediated PostgreSQL, not native bank-service/network containment.
- Built-in rules, GoRules ZEN 2.1.3, OPA 1.22.2, NeMo 0.24.1 literal detection and Promptfoo 0.125.1 literal assertions consume captured evidence. Exact field mappings determine applicability; absent evidence remains Unknown, absent mapping remains Not evaluated. Semantic model-based rails are not deterministic policy verifiers.
- Existing model configuration and scoring remain unchanged. Added software controls are explicitly labelled as software, never real model results. Real OpenAI/Anthropic/Gemini SDK tool contracts are tested only with offline transports against real component state; no provider credential is resolved.
- Both Admin and RL Engineer configure and execute without another policy-configuration approval queue. Only Admin configures infrastructure profiles. An Engineer executing an Admin-authored plan does not inherit Admin's report-review exemption.
- GCP profile versions, source/generation-bound Build/Storage/Compute adapters, durable dispatch journals and a separate metadata-bound worker are present but inactive. A configuration is never shown as cloud-qualified merely because its schema or API mock passed.
