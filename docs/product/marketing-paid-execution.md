# Marketing execution integration

This is Anvil plumbing for the unchanged published five-role Marketing graph,
not a new Praxis authoring contract. Initial role-contract and native planning
package helpers are local software only; route integration, SQL admission, SDK broker
integration, role sessions, actual graph execution and independent runtime/image
qualification remain required before QA readiness or paid dispatch.

Migration105 and the local preparation/broker branches are now implemented but
not serving in QA. The separate Marketing feature switch defaults off. A generic
KYC technical qualification cannot qualify Marketing: the installed component
proof must cover the exact five-role graph and twelve-window runtime. A valid
Marketing SDK admission and complete native campaign execution remain unverified.

`marketing_paid_session.task_context` checks the exact retained public actor,
resolved binding, imported task revision/payload, template qualification,
campaign dataset and active qualification, complete US pair membership and
current runtime/broker fingerprints. Native metadata freezes those receipts;
a later source/receipt cannot silently replace them. Unsupported uploaded
campaign input adapters and other locale runtimes remain explicit Anvil gaps,
with no fallback to a different data population.

`marketing_paid_package.prepare` persists one deterministic public planning ZIP
per authored task and exact source/runtime epoch. The ZIP contains the public
actor, admission metadata and package manifest, never the original private
authored reference or future campaign data. Whole-dataset assignments create
case episodes rather than new authored tasks. Helper persistence/idempotence
controls use manufactured metadata and are not genuine task qualification.

The task remains one reusable campaign, with five roles sharing a campaign world
for each case. The full twelve-window protocol and its two revision rounds and
400-transition bound remain unchanged. Primary comparisons use the same saved
candidate across all five roles. Mixed teams, if added, are a separate method.

## Role contract

`marketing_paid_contract.phase` accepts only a real published agent node, its
exact declared input artifact names, a window1–12 and a bounded node visit. The
role and tool catalogue come from the immutable published graph. The outer host
must prove those artifacts' actual source, release and role visibility; this
pure helper does not grant that authority.

The internal tool-agent envelope supports `actions` OR an `artifact` for the
current node. Combining tool effects with completion before observing results
is rejected. This is harness control, analogous to the existing KYC tool-agent
turns, not extra mandatory fields in Praxis or in the task's final output.
Actions must match the role's exact tool IDs and input schemas. Candidate node
artifacts remain untrusted work: they cannot approve spending, assert clearance
or replace actual controller state and separately evaluated evidence.

Prompts retain the current node's inputs and observations and only its published
role's tool input contracts. Oversized context is an explicit Anvil error; the
renderer does not silently drop observations or task instructions. It performs
no provider calls and has no access to credentials or private expectations.

The published final campaign schema remains unchanged. Its existing `oneOf`
alternatives distinguish `campaign_closed` and `awaiting_authority`. The bounded
Marketing validator implements those exact alternatives, with strict typed JSON
equality. It does not weaken the published schema to fit the older validator.
Closure additionally requires the host's completed twelve-window graph and
durable weekly/closeout references. An early limit may produce an honest hold;
it is not a completed full campaign or a qualified benchmark result.

## Admission and integration requirements

Migration105 is reserved for separate Marketing execution/role-turn bindings.
Marketing must not impersonate a banking trial or borrow
`banking.paid_agent_bindings`. Its plan binds one campaign case, the exact
resolved task/template, dataset, source/runtime/evaluators, graph and current
saved model/key version. Five role sessions use that same candidate and actual
shared controller state, role-scoped MCP tools and persisted handoffs.

Reuse the existing API-only SDK broker, physical concurrency slots, current
Admin/rights/model/source/revocation gates, pilot policy, shared execution budget
and aggregate run reservation. Generate any required exact manifest server-side
from the saved Run configuration; do not introduce another key or manual manifest
ceremony. Commit intent before effects. Ambiguous SDK, tool or workflow effects
are not retried or reclaimed. Simulated approval/Task3 nodes remain host effects,
never extra agents, real approvals or generated media.

The Marketing-only physical slot bound may be1–1000 per case, within the existing
1000-slot aggregate group ceiling. KYC keeps its100-turn bound. Quote every
reserved slot and enforce the approved $2 aggregate ceiling. If the full bound
does not fit, reject with the actual estimate; do not trim cases, weeks or roles
or raise the cap automatically. The simulated campaign business budget is
separate from provider spending.

The campaign elapsed timeout remains1–600seconds for the entire case, including
all roles and windows. The Marketing UI should default to600 within this existing
bound. This does not promise that108+ actor outputs fit the deadline. Each broker
dispatch receives actual remaining time; an expired campaign stops before a new
claim or tool effect, preserves prior custody/reservations, and remains incomplete.
It must not silently drop windows, roles or cases to produce a success result.

The trusted role adapter commits a role-turn intent before the SDK callback and
requires the exact completed broker response before opening role tools. Its MCP
hook commits a correlated action intent before actual OpenEnv I/O. Tool receipt,
controller state and grader-only post-state projection commit together; failed or
ambiguous effects cannot be replayed. Application and scheduler roles cannot read
that private projection. Physical IDs and whole-state hashes retain custody;
the smaller post-state projection has its own independently checked hash.

Current local evidence covers negative admission/RLS, actual MCP hook ordering
and denied-write isolation, bounded preparation, broker domain separation,
ambiguous-dispatch handling and a deadline check. It does not cover positive
105 SDK admission, the complete API/worker/Harbor path, activated fixture-world
transitions, Marketing ordinal grading/calibration, exact-image qualification,
or serving QA readiness. Those remain Anvil implementation/qualification work.

The API now has a separate Marketing preparation branch and a status-only
failure finalizer. A worker cannot certify success through the generic task
finalizer. Failure disposition preserves ambiguous SDK/tool/workflow intents and
reservations; its narrow status RPC returns booleans rather than granting the API
access to private tool or workflow rows. Successful durable Marketing completion
and the scheduler/Harbor graph entry remain unfinished.

Independent review found and corrected a private capture episode-binding gap.
One separately owner-approved frozen SQL control accepted the assigned episode,
rejected a same-project foreign episode and changed generation, and retained
three one-way intents with only one actual receipt/projection. Its source, budget
and completed SDK ledger were manufactured local records; it proves neither
genuine-source qualification nor an actual SDK request. Later deadline/heartbeat
changes require their own evidence and do not inherit that frozen pass.

## Anvil-owned campaign provisioning

`marketing_campaign_provisioning.candidate` verifies an operator-supplied private
pack against its exact checksum-file fingerprint. It rejects escaping/symlinked
paths, changed contents and unsupported case identity/locale. The current source
pack contains272files/108,578,167bytes; its operator-only verification limit is
128MiB, with16MiB per file. Public upload and per-episode limits are unchanged.
The candidate manifest selects the two supported US cases. Other locale data may
be checksum-verified as retained source without being activated or qualified.

`persist` is a privileged operator helper for the existing registry; normal
application/scheduler roles cannot insert candidates. It preserves immutable
dataset identity/version/content/source and idempotently returns an unqualified
reference. No qualification record, Admin review, model request or Run authority
is created. A changed source epoch needs a new Anvil dataset version. Integrating
this helper into the existing operator path remains Anvil work; Praxis does not
create environments, fixture archives or evaluator qualifications.

Only the public dataset reference/membership belongs in discovery. The fixture
manifest, private alternatives and operator paths remain private. Runtime loading
must verify those bytes again and enforce release/branch/role boundaries. The
local candidate plan is an observed checksum result, never independent review or
semantic approval. Reference-only loading does not implement alternative-world
activation, simulated approvals or Task3 production.

## Fingerprint provenance

Praxis wire actor/template/binding/context/execution fingerprints and Marketing
OpenEnv/tool receipt arguments/results use RFC8785, matching their producers.
Execution identity in phase intents, the durable graph journal, MCP binding and
paid plan binding follows that same wire fingerprint. Local project snapshots,
broker metadata and normalized diagnostic views retain their separate existing
sorted-JSON protocol. The global metadata hash function is unchanged. Numeric
values such as1.0,1e-7 and-0.0 are covered by producer-specific controls; a hash
consumer must not substitute another encoding and call the resulting mismatch
an agent failure.

Dynamic request/action IDs belong to trusted runtime custody. Join them to frozen
logical obligations and actual effects; Praxis cannot know future UUIDs, and
candidate writes cannot establish their own semantic correctness. Original
Marketing0–4 anchors, group weights, critical rules and human/calibration gaps
remain separate from software execution evidence and its diagnostic ratios.
